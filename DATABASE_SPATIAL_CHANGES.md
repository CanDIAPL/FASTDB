# Database Changes on `spatial-id-rootid-replacement` Branch

This branch implements **spatial UUIDs** - deterministic identifiers that encode sky position for conflict-free multi-master replication.

## 1. `2026-01-07_001_procver_compact_id.sql`

**Purpose:** Support for spatial_id generation and position-based grouping

### Creates: `procver_compact_id` table

Maps `base_processing_version` UUIDs to compact 16-bit integers for encoding in spatial_id:

```sql
CREATE TABLE procver_compact_id (
    procver_id UUID PRIMARY KEY REFERENCES base_processing_version(id),
    compact_id SMALLINT UNIQUE NOT NULL GENERATED BY DEFAULT AS IDENTITY
);
```

### Creates: `spatial_group(UUID)` function

Extracts top 48 bits of HEALPix from a spatial_id (~0.05" resolution for exact position matching):

```sql
SELECT spatial_group(spatial_id) FROM diaobject;
```

### Creates: `idx_diaobject_spatial_group` index

Functional index on `spatial_group(spatial_id)` for efficient grouping queries.

## 2. `2026-01-12_001_add_spatial_id.sql`

**Purpose:** Add `spatial_id` column to `diaobject` as a separate deterministic identifier alongside the existing `rootid`

### Adds:

- **Column** `spatial_id UUID` on `diaobject`
- **Functional index** `idx_diaobject_spatial_group` on `spatial_group(spatial_id)`

### Rationale

The `spatial_id` is a deterministic UUID encoding sky position, observation time, processing version, and data release. It is added as a **separate column** alongside the existing `rootid` (which retains its FK to `root_diaobject`). This additive approach preserves backward compatibility while enabling spatial queries and multi-master conflict-free identifiers.

## 3. `2026-01-20_001_matching_group.sql`

**Purpose:** Proximity query functions for finding objects within ~1 arcsecond

### Creates: Morton Code Helpers (Internal)

| Function | Description |
|----------|-------------|
| `_mg_undilate(BIGINT)` | Extract alternating bits from Morton code |
| `_mg_dilate(BIGINT)` | Spread bits for Morton code |
| `_mg_xy_to_morton(BIGINT, BIGINT)` | Convert (x,y) to Morton code |

### Creates: Core Matching Functions

| Function | Description |
|----------|-------------|
| `matching_group(UUID)` | Extract coarse HEALPix (NSIDE=2^14, ~12.6" cells) |
| `matching_group_neighbors(BIGINT)` | Get cell + 8 HEALPix neighbors (returns array of 9) |

### Creates: Precision Functions

| Function | Description |
|----------|-------------|
| `_mg_nside_for_precision(FLOAT)` | Calculate NSIDE for given arcsec precision |
| `_mg_shift_bits_for_nside(BIGINT)` | Calculate bit shift for target NSIDE |
| `matching_group_at_precision(UUID, FLOAT)` | Parameterized matching (1", 10", 100") |
| `matching_group_neighbors_at_precision(BIGINT, FLOAT)` | Neighbors at given precision |
| `matching_precision_info(FLOAT)` | Returns NSIDE, pixel size, total pixels |

### Creates: `idx_diaobject_matching_group` index

Functional index on `matching_group(spatial_id)` for efficient proximity queries.

### Performance Note

All functions are marked `PARALLEL SAFE` for query parallelization across multiple CPU cores.

## Architectural Change

### Before (rootid only)

```
┌─────────────────┐     ┌─────────────────┐
│ root_diaobject  │◀────│    diaobject    │
│   id (UUID PK)  │ FK  │ rootid → id     │
│   ra, dec       │     │                 │
└─────────────────┘     └─────────────────┘

Problem: Same object on different writers → different random UUIDs → replication conflicts
```

### After (rootid + spatial_id)

```
┌─────────────────┐     ┌──────────────────────────────────┐
│ root_diaobject  │◀────│           diaobject              │
│   id (UUID PK)  │ FK  │ rootid → root_diaobject.id       │
│   ra, dec       │     │ spatial_id (deterministic UUID)   │
└─────────────────┘     └──────────────────────────────────┘

Benefit: spatial_id is deterministic — same inputs on different writers → identical UUID
         rootid + root_diaobject retained for backward compatibility
```

## UUID Bit Layout

```
High 64 bits: [Reserved:2][HEALPix:62]
Low 64 bits:  [MJD_ms:43][ProcVer:16][DataRelease:5]
```

| Field | Bits | Range | Purpose |
|-------|------|-------|---------|
| Reserved | 2 | 0 | Future use |
| HEALPix | 62 | NSIDE=2^29 | Sky position (~0.0004" resolution) |
| MJD_ms | 43 | 278 years | Observation time (millisecond precision) |
| ProcVer | 16 | 0-65535 | Processing version (via procver_compact_id) |
| DataRelease | 5 | 0-31 | Data release (0=realtime) |

## Function Resolution Comparison

| Function | Resolution | Use Case |
|----------|------------|----------|
| `spatial_group()` | ~0.05" | Exact position matching (same object) |
| `matching_group()` | ~12.6" | Proximity queries (< 1" matching) |
| `matching_group_at_precision(_, 1.0)` | ~0.4" | Fine proximity matching |
| `matching_group_at_precision(_, 100.0)` | ~100" | Coarse area filtering |

## Usage Examples

### Find objects at same position (exact match)
```sql
SELECT * FROM diaobject
WHERE spatial_group(spatial_id) = spatial_group(:target_spatial_id);
```

### Find objects within ~1 arcsecond (proximity)
```sql
SELECT * FROM diaobject
WHERE matching_group(spatial_id) = ANY(
    matching_group_neighbors(matching_group(:target_spatial_id))
)
AND q3c_join(:target_ra, :target_dec, ra, dec, 1.0/3600);
```

### Query precision information
```sql
SELECT * FROM matching_precision_info(10.0);
-- Returns: nside=16384, pixel_size_arcsec=12.59, total_pixels=3221225472, shift_bits=30
```
